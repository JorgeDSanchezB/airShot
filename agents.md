# agents.md — Registro de trabajo y contexto operativo para agentes

Este archivo es la memoria de trabajo del repositorio AirShot. Se actualiza **al final de cada fase** del flujo de arquitectura (instrucción del enunciado). Cualquier agente que retome este proyecto debe leer primero `docs/architecture.md` y este registro.

## Contexto del proyecto

- **Entregable actual**: documento de arquitectura y planificación (`docs/architecture.md`) + ADRs (`docs/decisions/`). **No hay código de AirShot implementado** (fase 6 queda como esqueleto preparado, por decisión explícita del enunciado).
- **Stack objetivo (especificado, no implementado)**: FastAPI + Pydantic v2 (backend), React 18 + TS + Vite + shadcn/ui + Zustand + TanStack Query + react-virtual (frontend), SQLite + SQLAlchemy 2.0 async + Alembic, FFmpeg subprocess, proveedores externos intercambiables.
- **Método de trabajo obligatorio**: loop planifica → construye → prueba → revisa → corrige → repite, con árbitro adversarial independiente por fase y sobre el entregable final. El árbitro solo puede aprobar verificando uno a uno los puntos del LISTÓN (ver `docs/architecture.md` §0 y «Informe del Árbitro»).
- **Reglas no negociables**: cero hardcoding (todo límite en `config.yaml`/`providers.yaml`); extensibilidad sin tocar núcleo (Strategy+Factory para proveedores, JSONB+JSON Schema para atributos); paginación por cursor en todo listado; virtualización y claves UUID en frontend; taxonomía de 7 tipos de error; anti-sobreingeniería (problema/coste/alternativa en cada patrón); honestidad epistémica (no afirmar ejecuciones no reproducibles).
